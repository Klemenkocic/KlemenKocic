## Throughline

I used to carry coaching knowledge in my head. Now I'm teaching a system to carry it. Here's what that actually looks like, technically — and what it tells us about where software is going.

Each post pairs a concrete Charles thread with a broader observation about the agent era. Some lean personal, some lean systems.

---

## The 9 posts

**1. The PT background + the data problem.**
I was a personal trainer and nutrition coach. The first technical problem was taking what lived in my head and turning it into something an AI can reason over. Bigger thread: most failed AI products skip this step. They throw vague context at the model and hope. Real systems start by structuring the expertise.

**2. The adaptation problem + the end of frozen software.**
Plans always change. Injuries, vacations, shifting goals. The hard part of coaching was never the first plan, it was the rebuild. Bigger thread: software used to be frozen at install time. AI-native software is the opposite. It learns, it rebuilds itself, the version you used yesterday isn't the version you use today.

**3. Surgical AI.**
Six layers of filtering before the model sees data. AI does what's genuinely hard to code, code does the rest. Bigger thread: the "throw it all at the LLM" era is ending.

**4. The end of the app store.**
People are already saying "send this GH link to your agent and it'll set it up." That's not a prediction, it's now. In a few years there won't be an app store. You'll talk to an agent and it will install, configure, and connect things for you. Charles thread: even today, Charles assembles a plan around your inputs without you ever touching settings. The whole config layer disappears.

**5. Hidden complexity.**
Cal.ai angle. The user doesn't need to understand periodisation. The science lives in the system. Bigger thread: expertise that used to be sold as consulting is becoming infrastructure. The advantage moves from knowing things to building the systems that hold the knowledge.

**6. Structural enforcement.**
Rules don't scale. You don't tell the system "remember to do X," you build it so X happens automatically. Charles example: cache invalidation tied to navigation. Bigger thread: this applies anywhere agents are involved. Product, organisations, workflows.

**7. Memory and reversibility.**
Charles tracks every swap, every adaptation, every reason. You can see why the system did what it did. Bigger thread: as agents take more action, the audit layer becomes the product. "Why did it do that" and "undo it" are the new requirements, and most AI systems don't have either.

**8. Multi-model.**
Charles can run on Gemini, Claude, or others. The model is a swappable component. Bigger thread: betting your product on one provider is the new vendor lock-in. The orchestration layer is where the real work lives.

**9. Meet Charles.**
Reveal. Screenshots. Live on the App Store. Try it.
